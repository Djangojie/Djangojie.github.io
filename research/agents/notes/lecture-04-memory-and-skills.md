这节课可以先用一个日常例子理解：

> 第一次去商店找耳机，你摸索出了搜索、筛选、查看商品的方法。下一次找键盘时，就可以沿用这套方法。  
> Agent 的记忆与技能，就是让它保存有用经历，并把重复操作整理成以后能用的方法。

与前面三课的关系是：

```text
第一课：Agent 怎样围绕目标行动
第二课：怎样调用工具
第三课：历史越来越长，怎样处理上下文
第四课：历史里哪些东西值得留下，怎样变成可复用的经验
```

## 第 1–6 页：什么值得记住，什么可以变成技能

**第 1 页｜记忆与技能**

副标题可译为：**Agent 怎样在积累经验后改进，而不用每次从头开始。**

这里讲的改进，主要通过保存、检索和使用外部资料实现，通常不需要重新训练模型。

**第 2 页｜不同任务有共同步骤**

课件比较两个任务：

- 把 Sony 耳机加入愿望清单。
- 查无线键盘的价格范围。

两者都要先进入商店、找到搜索框、填写关键词、提交搜索；后面才分别执行收藏或读取价格。

**意思：**任务不完全相同，但其中一部分操作可以复用。课程接下来研究：这部分方法应写成文字还是代码？怎样从经历中提炼？什么时候使用、更新或删除？

**第 3 页｜让 Agent 获得经验的三个位置**

| 放在哪里 | 可以理解为 | 好处 | 代价 |
|---|---|---|---|
| 当前上下文 | 把之前的过程一直摆在面前 | 保留具体经过 | 越来越长，也混着无用信息 |
| 外部文件或记忆库 | 需要时查笔记、操作手册 | 可查看、修改、检索和迁移 | 要决定记什么、找什么、怎样维护 |
| 模型参数 | 通过训练改变模型本身 | 可影响更广的行为 | 更新较慢，也不容易检查具体记住了什么 |

**意思：**本课重点是中间一项：把经验变成外部可用的材料。

**第 4 页｜三类经验**

- **经历 Episode：**一次任务的完整过程，包含看到什么、做了什么。
- **事实 Fact：**例如“这个商店只有进入商品详情页才显示价格”。
- **技能 Skill：**例如“填写搜索框，然后点击搜索，再打开结果”。

**意思：**完整经历、事实和操作方法有不同用途，不一定都要保存成同一种形式。

**第 5 页｜记忆和技能是什么关系**

课件采用的区分是：

- **记忆：**保存自 Agent 自己的交互经历。
- **技能：**可重复使用的行动知识，可以是文字、代码，或两者结合。

因此，用户写的一份发布检查清单属于技能；Agent 从自己成功搜索的经历中总结出来的方法，既来自记忆，也是一项技能。

**意思：**“记忆”强调从哪里来，“技能”强调以后能怎样使用，两者可以重叠。

**第 6 页｜技能的两条来源**

1. **人写出来：**把已有经验、规则和文档整理给 Agent。
2. **Agent 总结出来：**从自己的操作与结果中发现可复用的方法。

**意思：**前者需要人花时间编写维护；后者需要可靠地判断成功与失败，避免把错误方法保存下来。

## 第 7–15 页：人编写的技能

**第 7 页｜章节页：人工编写的技能**

开始介绍人怎样把做事要求交给 Agent。

**第 8 页｜什么是一项技能**

例子是每次审查 Python 代码，都要重复说明：

> 按团队规定格式化代码，运行检查，检查类型标注、文档和测试。

把这套要求整理成一份可以反复使用的材料，就形成了技能。它可以包含说明文档、脚本和资源文件。

**意思：**不用每次重新输入整套要求，也更容易让多次执行遵循同一标准。

**第 9 页｜一份技能包长什么样**

课件展示的目录大致是：

```text
python-review/
├── SKILL.md       技能名称、适用场景、操作说明
├── scripts/       可以运行的脚本
├── references/    详细参考资料
└── assets/        模板等资源
```

加载时分三层：

1. 先知道技能的名称与简介。
2. 需要使用时，再读操作说明。
3. 需要某项资料时，再打开相关文件。

**意思：**先看目录，需要时才读正文，避免一次把整套资料塞进上下文。这叫 **渐进式披露 Progressive Disclosure**。

**第 10 页｜先让 Agent 看到技能索引**

课件展示一个系统提示词示例：列出技能名称和适用场景，并告诉 Agent 如何加载。

**意思：**Agent 要能先发现“有这项技能”，才可能在合适的时候使用。简介写得不清楚，就可能选错或漏选。

课件中的提示词是研究对象，不是要求所有 Agent 都采用同一条加载规则。

**第 11 页｜加载和执行时，什么进入上下文**

以代码审查技能为例：

```text
看到技能简介
    ↓
读取 SKILL.md 的操作步骤
    ↓
运行检查脚本，取得检查结果
    ↓
需要更详细规则时，再读取参考文档
```

课件强调：运行一个脚本时，可以只把输出交给模型，不必把全部脚本代码都读入上下文。

**意思：**工具执行和模型阅读是两件事。设计得当，可以减少模型需要阅读的内容。

**第 12 页｜技能有没有帮助：SkillsBench**

课件介绍一个评估：

- 87 个任务，覆盖 8 个领域。
- 人工为任务挑选配套技能。
- 比较有技能和没有技能的表现。
- 涉及 18 种模型与运行程序组合。

**意思：**这里测的是“提供人工挑选的技能后有没有帮助”，没有直接证明 Agent 总能自己找到正确技能。

**第 13 页｜技能的收益与限制**

课件报告平均通过率从 **33.9% 提升到 50.5%**，增加 **16.6 个百分点**。

但也有 **13 个任务表现下降**。较聚焦、较短的技能组与较大的收益有关。

**意思：**技能可能帮助，也可能干扰。不能推断“技能越多越好”；这些结果限于该实验设置。

**第 14 页｜技能可以从哪里来**

课件列出三类：

- Agent 系统自带。
- 用户自己编写或从其他仓库安装。
- Agent 根据刚完成的工作生成。

课件引用的实践建议是：在 Agent 刚完成一套你想重复的流程后，及时整理技能，再多试几次。

**意思：**刚完成的流程有具体材料可参考，比凭空写一份万能操作手册更容易检查。

**第 15 页｜技能也要维护**

课件以代码审查为例：

```text
运行技能 → 记录结果 → 评价表现 → 找反复出现的问题 → 修改技能
```

例如，反复发现 Agent 没有遵循仓库惯例，就可以补充要求：提出建议前先核对仓库实际做法。

**意思：**技能不是写完就永久有效，应该根据执行结果修订。课件中的“人采纳了多少建议”也是一种评价线索，不能完全等同于建议的真实质量。

## 第 16–20 页：保存事实、教训和完整经历

**第 16 页｜章节页：记忆**

开始介绍事实、经验教训和任务经历怎样保存与使用。

**第 17 页｜管理外部记忆**

课件展示 MemGPT：当前上下文容量有限，Agent 可以调用函数，把资料存到外部，也可以搜索并取回。

**意思：**像做事时桌面只能放几张纸，其余资料存进档案柜，需要时再取出。能否取回，取决于保存方式和检索能力。

**第 18 页｜记忆冲突怎么办**

新信息到来后，可以：

| 操作 | 使用情形 |
|---|---|
| ADD，新增 | 之前没有类似信息 |
| UPDATE，更新 | 已有内容发生变化 |
| DELETE，删除 | 新信息否定了旧记忆 |
| NOOP，不处理 | 已经保存，或者不值得保存 |

**意思：**记忆系统不能只会不断追加。例如“我已经搬家了”，应更新地址，而不是把新旧地址都当成当前事实。

**第 19 页｜记住对失败过程的反馈**

Reflexion 的例子中，Agent 第一次回答了某一场战役的名字，但问题问的是一系列战役。反馈指出这一点，第二次改成了战役群所属的整体名称。

**意思：**有用的反馈应指出“错在哪里、下次如何调整”。不过反馈本身也可能错，所以还需要检查结果。

**第 20 页｜找相似的旧任务作为例子**

系统保存过去的成功或失败过程。新任务到来时，检索最相似的几次经历，放进上下文供 Agent 参考。

**意思：**像先看别人做过的相似题。但相似经历可能很长，也可能只是表面相似，不能直接照抄。

## 第 21–30 页：怎样从经历中提炼技能

**第 21 页｜章节页：归纳技能**

这里的“归纳”，可以理解为：从具体操作中总结出可重复使用的方法。

**第 22 页｜把任务切成可复用的小块**

例如：

```text
搜索商品(query)
    ↓ 可以继续接
读取价格范围
```

搜索方法不必为“耳机”和“键盘”分别保存一份，可以把商品名称变成参数 `query`。

**意思：**技能通常是任务中的一个可复用部分，不一定包办整个任务。

**第 23 页｜已有研究怎样生成技能**

课件介绍一些不同方向：

- **Voyager：**在 Minecraft 中生成动作函数，复杂技能可以调用已有技能。
- **DreamCoder、Stitch：**从多段程序中找共同结构，提炼函数。
- **LAPS、LILO：**结合自然语言描述和程序生成、整理技能。

**意思：**技能发现既可以从自然语言经历中总结，也可以从代码的重复结构中提取。

**第 24 页｜边做任务，边积累技能**

任务按顺序到来。Agent 完成当前任务后，把总结出的技能保存；后面的任务可以使用它。

**意思：**评估的不只是每道题独立做得怎样，还包括 Agent 能否从前面的题中积累经验。

**第 25 页｜技能的一生**

```text
学习：完成任务 → 判断结果 → 总结技能 → 检查后保存
使用：找到技能 → 执行 → 观察结果
维护：根据结果新增、修复或淘汰技能
```

**意思：**生成技能只是开始，后续选择和维护同样重要。

**第 26 页｜生成文字技能**

例子是搜索评论：

1. 打开评论页。
2. 输入 “satisfied”。
3. 点击搜索。
4. 读取结果。

Agent 可以把特定搜索词替换为 `{term}`，总结成“搜索包含某个词的评论”。

**意思：**把一次具体经历变成可套用的方法。但页面元素 ID 等信息可能改变，仍需要适应当前页面。

**第 27 页｜怎样提示模型提炼技能**

课件展示的提示词要求模型：

- 找多个任务里反复出现的步骤。
- 提炼经常复用的小流程。
- 避免生成重复、重叠的流程。
- 把可变内容改成有意义的参数。

**意思：**希望得到的是通用方法，而不是把每个旧任务换个标题存起来。

**第 28 页｜跨任务积累经验的效果**

图中的例子从“按名字找地点”，逐步复用到“找附近咖啡馆”“查询路线”“判断能否及时到达”等任务。

**意思：**基础技能可以帮助完成后续更复杂的任务。图里展示的是特定实验中的累计成功率，不能理解为技能积累一定让表现持续上升。

**第 29 页｜技能写成文字还是代码**

| 表达形式 | 优点 | 代价 |
|---|---|---|
| 文字与示例 | Agent 可以结合当前情况调整 | 仍需要逐步理解并发出操作 |
| 可执行代码 | 可测试、可组合，一次调用可完成多步 | 页面或条件改变时可能失效 |

**意思：**文字更灵活，代码能固定并自动执行更多步骤，选择取决于流程是否稳定。

**第 30 页｜生成代码技能**

同样的评论搜索任务，可以拆成两个函数：

```python
open_marketing_reviews()
search_reviews(search_box_id, search_button_id, search_term)
```

执行任务时组合使用。

**意思：**把重复操作封装起来，让后续任务少做低层重复决策。函数生成后仍要检查和测试。

## 第 31–36 页：代码技能的好处与脆弱之处

**第 31 页｜代码技能可以先测试**

课件展示一个技能参数 `color` 定义了却没有使用的例子。检查发现问题后，补充真正选择颜色的操作。

**意思：**函数存在、代码能运行，不代表它正确使用了参数。应测试技能执行后是否达到目标，再决定是否保存。

**第 32 页｜代码技能压缩任务步骤**

图中一个购物网站例子：没有记忆时达到 50 步上限；使用代码技能后，Agent 只需 4 步。

**意思：**这里主要减少的是 **Agent 与工具之间的决策轮次**。技能内部仍然可能执行很多浏览器动作，不是所有实际操作都消失了。

**第 33 页｜代码技能的实验结果**

课件报告五个 WebArena 网站的平均结果：

| 方法 | 到达的任务检查点比例 | 每任务平均步数 |
|---|---:|---:|
| 没有记忆 | 41.3% | 24.5 |
| 文字技能 | 59.5% | 20.6 |
| 代码技能 | 80.2% | 15.0 |

**意思：**在这些具有重复结构的网页任务中，代码技能推进了更多检查点，也减少了 Agent 步数。**检查点比例不是完整任务成功率**，不能说“80.2% 的任务全部完成”。

**第 34 页｜技能能迁移到另一个网站吗**

一个网站的排序入口可能是下拉菜单，另一个网站却是侧边栏。直接执行原来的点击代码就可能失败。

**意思：**“把商品排序”的目标可以通用，具体点击方式却不一定通用。

**第 35 页｜PolySkill：统一接口，不同实现**

上层统一调用：

```text
搜索商品
加入购物车
结算
```

每个网站分别实现自己的底层操作。

**意思：**像不同品牌的车都有“刹车”这个功能，但内部实现可以不同。上层流程复用，网站差异集中在底层适配。

**第 36 页｜三种保存方式的取舍**

- **完整旧经历：**保留细节多，但长，而且不容易迁移。
- **文字技能：**提供灵活指导，但执行时通常仍需要模型逐步操作。
- **代码技能：**可执行、可组合，但容易受到环境变化影响。

**意思：**关键问题是：哪些部分留给模型临场判断，哪些部分固定在文件或代码里。

## 第 37–43 页：失败、筛选、遗忘和训练

**第 37 页｜章节页：技能的生命周期**

进入“技能怎样长期保持有用”的问题。

**第 38 页｜从失败中学方法**

例子中，Agent 搜索 Sony 蓝牙耳机，得到 5,578 条结果，反复翻页，最终超过步数上限。

可以总结的教训包括：

- 先缩小搜索范围。
- 使用类别筛选。
- 适当增加每页显示数量。

**意思：**失败过程本身未必值得模仿，但可以从中提炼避免重复失败的策略。

**第 39 页｜失败对不同记忆形式作用不同**

图中加入失败经历后：

- Synapse 的成功率由 40.6% 到 41.7%。
- AWM 由 44.4% 降到 42.2%。
- ReasoningBank 由 46.5% 到 49.7%。

**意思：**存下失败动作供模仿，可能误导；把失败转成原因和应对策略，可能更有帮助。但图中的效果限于该任务、模型和实验，不能推广成所有方法的固定规律。

**第 40 页｜判断成功与否的“裁判”有多重要**

如果系统把失败当成功，就可能保存错误经验。课件通过人为翻转正确标签，模拟不同准确率的裁判，观察后续表现。

**意思：**经验库的质量取决于入口判断。但这种模拟错误与真实裁判的错误分布不同，不能直接当作真实系统保证。

**第 41 页｜一次找回太多经验，也会坏事**

图中取回 1 条经历时表现最好；继续增加到 2、3、4 条，成功率逐渐下降。

**意思：**经验越多，可能混入越多无关信息，也会增加模型处理负担。应该检查取回的经验是否相关，而不是只追求数量。

**第 42 页｜记忆整理与遗忘**

课件介绍一种做法：根据函数的使用次数，清理很少使用的函数，使技能库不至于无限增长。

**意思：**技能需要整理、合并和淘汰。不过低频不一定无价值；实际系统还应考虑重要程度，不能机械套用课件中的删除规则。

**第 43 页｜怎样训练 Agent 生成真正有用的技能**

只看第一个任务成功，无法判断保存下来的技能是否有价值。课件提出把相关的后续任务一起纳入训练：

```text
任务 1 成功
    ↓ 保存技能
任务 2 使用该技能，并成功
    ↓
才获得“技能复用有效”的反馈
```

**意思：**技能的价值要通过后续使用检验。“生成了一份漂亮的技能文件”不等于它能帮助未来任务。

## 第 44–46 页：谁来决定记什么、用什么

**第 44 页｜哪些东西应该长期留下**

课件提出几个取舍：

- 保留具体经历，还是总结通用方法？
- 用灵活的文字，还是固定执行的代码？
- 继续复用旧方法，还是探索替换？
- 增加记忆，还是更新、合并、删除？

**意思：**记忆管理是在不同收益和代价之间选择，不能只看“保存了多少”。

**第 45 页｜人与 Agent 分别负责什么**

| 决定 | 人更适合投入的情况 | Agent 更适合投入的情况 |
|---|---|---|
| 创建技能 | 规则、政策已经明确 | 需要从反复交互中发现方法 |
| 验证是否保存 | 涉及规范、高风险判断 | 结果容易执行和测试 |
| 选择使用 | 有少见例外，需要具体判断 | 场景重复，能持续取得反馈 |
| 长期维护 | 需要明确责任人 | 问题能从运行结果中观察并修复 |

**意思：**可以让 Agent 承担更多重复工作，同时保留适当的人类判断与责任归属。

**第 46 页｜结束与下一课**

下一课：**Planning，规划**。

---

第四课最值得你带走的是：**Agent 的经验要经过“保存、选择、使用、验证和维护”，才可能变成可靠能力。**

以你正在学习的代码审查为例：

```text
完整经历：这次审查了什么，执行了哪些检查，发现了什么
事实：这个仓库使用哪套检查规则
教训：某次漏检的原因，以及下次如何避免
文字技能：以后审查时遵循的步骤
代码技能：自动执行这些检查的脚本
```

这五种材料各有用处，后续任务需要哪一种，就选择哪一种。
