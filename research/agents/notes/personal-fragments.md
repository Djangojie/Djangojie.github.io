# 个人速记：原话、校正与待验证问题

来源：本轮 Obsidian 中的 `cmu11768 lecture2.md`、`cmu11768 lecture3.md` 和 `openai docs.md`。以下引号内保留用户原始速记，解释栏为本轮 AI 辅助校正。原笔记内嵌截图不再转载，对照 [第二课](lecture-02-tool-use.md)、[第三课](lecture-03-long-context.md)、[第四课](lecture-04-memory-and-skills.md) 与 [论文阅读卡](papers-and-evidence.md) 回查。

| 原始速记 | 整理与校正 | 下次怎样验证 |
| --- | --- | --- |
| “调用代码工具比单独执行的效果” | 这是比较问题，原句未写清基线和结果，不能改写成“代码工具一定更好”。 | 说明比较谁与谁、任务、工具权限、成功率和预算。 |
| “时间限制可以使得模型更快的完成任务” | 时间约束可能改变策略，但是否更快、是否牺牲正确率需要实验；不能仅从提示词写了期限得出效果结论。 | 固定任务和模型，对照有无期限，记录耗时与成功率。 |
| “滑动窗口注意力 规定窗口w在此之间检索” | 更准确地说，在这种注意力设计中，每个位置只直接关注限定邻域；它与外部文档检索不是同一操作。 | 画出每个位置可见的窗口和遮罩。 |
| “线性把记忆大小固定压缩到s矩阵，在其中进行检索” | 这是对线性注意力状态的直觉：某些形式用固定形状状态累计历史信息，再用查询读出；状态形状不随序列长度增长，不代表无损记住任意细节。 | 用很短序列画出状态更新，再对比完整注意力能保留的信息。 |
| “deltanet 根据已有信息进行一个预测，拿预测与结果做差再次预测” | 应区分“用误差更新记忆”与“再做一次输出预测”。学习重点是 delta rule 根据键对当前值的预测误差修正状态，仍需回到课件公式核对。 | 写出旧状态、预测、目标值、误差、更新后的状态；尚未实现验证。 |
| “分页管理kv cache” | 分页是缓存存储与分配方式，不等于把语义历史摘要或删短；与第三课的上下文压缩分开理解。 | 分别回答缓存存在哪里、模型能看哪些位置、历史消息删了哪些。 |
| “polyskill” | 对应第四课的 PolySkill：上层动作接口可以复用，具体环境实现可能不同。 | 选两个不同界面的“搜索”流程，比较相同接口与不同实现。 |
| “skillbench 跨领域任务，agent调用，关键步骤，可以完成原本完不成的任务” | 与 SkillsBench 的阅读方向一致，但收益限于指定任务、技能及配置；并非所有任务都会提升。 | 对照指定版本的实验条件与失败任务。 |
| “swe-skill 软件任务，先找skill再找对应的代码仓库，基本没有提升” | 对应 SWE-Skills-Bench 的技能出发点；总体提升小与所有单技能均无用不同。“未显著”也不代表证明零效果。 | 查看逐技能结果、统计检验与需求覆盖，避免仅看总平均。 |

这些短句的价值在于保留“当时抓住了什么”。整理后同时留下不确定性和验证动作，避免将速记中的类比固定成错误知识。
