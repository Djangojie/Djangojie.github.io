## 为什么按这个顺序做

```text
读验收要求和入口
  → 固定依赖与源码
  → 共享消息/工具循环
  → 编码工具和错误恢复
  → 云端配置与第一次实跑
  → 上下文压缩对照
  → 下棋工具与观察方式实验
  → 轨迹、补丁和报告
```

这与课程主线对应：工具调用让 Agent 能行动；上下文管理让它能继续；技能让某些流程可复用；轨迹与验证说明这些组合是否真的有效。

## 环境管理沉淀

本轮环境整理采用“新项目用 uv、旧项目保留 conda”。固定依赖由 `pyproject.toml` 与 `uv.lock` 管理，项目通过 `uv run` 使用自身环境。用户级 uv 入口已修复，但默认全局 `python` 仍是 conda base，二者不能混称为“全局 Python 已迁移”。

旧环境只做了解释器与依赖导出，没有逐个验证旧项目功能；未删除 conda 环境。完整路径、恢复脚本和导出清单保留本地，避免将与学习资料无关的系统信息发布到博客。

**整理推论：**环境可复现性应成为 Agent 实验记录的一部分。否则实验失败时，很难分清是推理策略问题、工具问题，还是依赖与运行环境问题。
