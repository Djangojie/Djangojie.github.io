## 第 1–5 页：为什么 Agent 会遇到长上下文

**第 1 页｜长上下文 Agent 的上下文管理**

副标题可以译为：**当 Agent 的工作历史不断增长时，如何让它继续工作。**

这里的“上下文”是模型当前能看到的材料，包括用户要求、系统指令、工具说明、之前的操作和工具返回结果。

**第 2 页｜Agent 上下文的增长**

章节过渡页。

**第 3 页｜历史线性增长，累计输入呈二次增长**

课件举例：每次调用都带上固定前缀和之前的历史。若每轮增加 5K token，连续五次输入分别为：

| 调用 | 该次输入 | 累计输入 |
|---|---:|---:|
| 第 1 次 | 6K | 6K |
| 第 2 次 | 11K | 17K |
| 第 3 次 | 16K | 33K |
| 第 4 次 | 21K | 54K |
| 第 5 次 | 26K | 80K |

**意思：**历史每轮只增加一点，但旧历史会一遍遍重新出现在后续请求中。上表说明的是**累计输入量**的增长，并不等于实际费用或运行时间一定按同样比例增长；缓存、模型架构和计费规则都会影响结果。

**第 4 页｜Agent 提示词由什么组成**

课件统计的 1,500 个 OpenHands 会话中，每个会话平均约 **77,922 token**。图中标出的主要部分包括：

- 系统指令和工具说明：23%
- 用户内容：9%
- 推理内容：9%
- 工具调用：20%
- 工具结果：37%

图里还有一段标为 2%，但截图没有显示它的类别名称。

**意思：**Agent 的上下文不只是你和它说的话。读文件、运行命令、查看日志产生的工具调用和结果，也会占据大量空间。这些比例是课件所选样本的统计，不代表所有 Agent 都如此。

**第 5 页｜长上下文的两个挑战**

1. **能力：**内容虽然放进去了，模型能否找到并用对其中的信息？
2. **效率：**处理这么多内容，时间、显存和费用是否可以接受？

**意思：**“能装下 100 万 token”和“能高效、准确地利用 100 万 token”是不同的问题。

## 第 6–11 页：模型处理输入和生成回答

**第 6 页｜大模型推理**

章节过渡页。这里的 *inference* 指模型接收输入并生成结果的运行过程。

**第 7 页｜一个请求经过哪些环节**

可以把图读成：

```text
请求进入
  → 调度器安排请求
  → 处理输入（Prefill）
  → 逐步生成输出（Decode）
  → 返回回答
```

模型运行时会保存 **KV cache**，即之前内容对应的一部分计算结果，供后续生成使用。

**意思：**模型服务不仅是“输入文字、输出文字”；系统还要安排计算、管理内存并复用中间结果。

**第 8 页｜Prefill 与 Decode**

- **Prefill，预填充：**先处理输入中的 token，建立相关的 KV 状态。
- **Decode，解码生成：**在已有状态基础上，一步步生成后续 token。

**意思：**长输入首先影响处理提示词的阶段；长回答则会增加后续逐步生成的工作。课件指出，前者通常更偏计算密集，后者常受到读取内存速度的影响。

**第 9 页｜衡量响应速度**

- **TTFT：首 token 时间。**从请求到达，到用户看到第一个输出 token 的时间。
- **TPOT：每个输出 token 的时间。**可以近似理解为生成过程中相邻 token 的平均间隔。
- **吞吐量：**单位时间内完成多少 token 或请求。
- **费用：**可能由普通输入、缓存输入和输出等部分组成。

**意思：**“等多久开始回答”和“开始后回答流出得有多快”是两种不同体验。

**第 10 页｜注意力机制回顾**

课件中的 `Q`、`K`、`V` 可以先这样理解：

- **Q，查询：**当前位置正在寻找什么。
- **K，键：**之前每个位置提供的匹配线索。
- **V，值：**匹配到后可以取用的信息。

模型比较 Q 和 K，得到注意力权重，再按权重组合 V。图中的遮罩让当前位置不能看到未来内容。

**意思：**注意力让当前 token 能参考前面的内容。长文本中，需要处理的历史越多，这一步的开销也会增长。

**第 11 页｜标称上下文与有效上下文**

图是一次“大海捞针”测试：把一个事实放在不同长度文档的不同位置，再让 GPT-4 找出来。

- 横轴：上下文长度。
- 纵轴：事实位于文档的什么位置。
- 颜色：该测试中的检索准确率。

图中部分较长上下文位置的准确率下降。

**意思：**模型支持某个最大长度，不保证能在所有位置都同样准确地找出信息。图反映的是**该模型、该测试和当时设置下**的结果，不能直接代表所有模型或复杂任务。

## 第 12–25 页：模型如何降低长上下文开销

**第 12 页｜长上下文架构**

章节过渡页。

**第 13 页｜标准注意力是全局的**

标准注意力通常需要让当前位置与可见的历史位置进行比较。

**意思：**能直接查看较完整的历史，但文本变长时，比较次数会快速增加。

**第 14 页｜局部建模**

每个位置只看附近固定范围的内容。课件用 `w` 表示窗口大小，`n` 表示文本长度。

- 标准的两两比较：大致是 \(O(n^2)\)。
- 固定窗口：大致是 \(O(nw)\)。

**意思：**如果每次只看附近一小段，文本增长时需要做的比较会少很多；但远处的信息不能被这一层直接看到。

**第 15 页｜混合模型定期进行全局访问**

模型连续使用若干较便宜的局部计算，再安排一次能访问更广范围历史的全局计算。

**意思：**兼顾日常计算成本和获取远处信息的能力。

**第 16 页｜不同模型的混合架构**

课件列出若干模型，比较其局部计算、全局计算，以及两类层的大致比例。

**意思：**它们的实现各不相同，但共同思路是：**不让所有层都对整个历史做同样昂贵的处理。**这页的模型名称、比例和后面价格表都应理解为课件中的信息，若要实际选型应另行核对最新资料。

**第 17 页｜四种反复出现的方法**

1. 滑动窗口注意力
2. 线性注意力或循环模型
3. 稀疏注意力
4. KV 压缩

接下来几页逐个解释。

**第 18 页｜滑动窗口注意力**

当前位置只看最近 `w` 个位置，窗口之外的历史不能被该层直接访问。

**意思：**像读书时只盯着当前段落附近。这样省计算，但如果答案在很久以前，就需要其他机制把信息传过来或重新找出来。

**第 19 页｜普通 Softmax 注意力**

模型保存过去各位置的 K、V，并让当前查询与历史中的键进行比较，再按权重读取值。

**意思：**保留较细的逐位置访问能力，但历史增长时，缓存和比较也会变大。

**第 20 页｜线性注意力**

课件展示一种简化推导：把过去信息逐步写入一个固定大小的矩阵状态 `S`，之后从这个状态读取。

**意思：**可以把它想成不再保存一整排逐字索引，而是不断更新一份“浓缩记忆”。好处是状态大小可以固定；代价是信息被压进同一份状态后，不同内容可能相互干扰。

**第 21 页｜DeltaNet：针对错误更新记忆**

更新时先读取当前记忆对新信息的预测，再计算预测与目标之间的差异，只根据差异做修正。

**意思：**类似先检查“我已经记得什么”，再重点改正有偏差的部分，而不是简单把所有新信息都往里叠。

**第 22 页｜Gated DeltaNet：增加整体遗忘**

在定向修正之前，先对整个记忆状态做一次衰减。参数 `α` 控制保留多少，`β` 控制修正强度。

**意思：**系统既能更新具体关联，也能逐渐淡化旧记忆。若 `α=1`，这一步不做整体衰减。

**第 23 页｜Kimi Delta Attention：更细地控制遗忘**

课件中的 KDA 让不同记忆通道有各自的保留程度，而不是所有部分统一衰减。

**意思：**从“整本笔记一起褪色”变成“不同类型的信息可以有不同保留时间”。这仍是模型内部机制，不等于它能像人一样有意识地决定哪些事实重要。

**第 24 页｜稀疏注意力**

只选择一部分历史位置进行注意力计算。课件比较两种选择方法：

- **固定模式：**预先规定看哪些位置，成本容易预测。
- **根据内容选择：**针对当前查询挑选位置，更灵活，但可能漏选相关内容。

**意思：**与其翻遍全部历史，不如先缩小查找范围；代价是选择阶段也可能出错。

**第 25 页｜KV 压缩**

图中比较四种缓存方式：

- **MHA：**各注意力头分别保留较完整的 K、V。
- **GQA：**多个查询头共享一组 K、V。
- **MQA：**更多查询头共享同一组 K、V。
- **MLA：**缓存压缩后的潜在表示，再用于恢复各头所需的信息。

**意思：**长上下文不只花计算量，也占显存。减少或压缩需要保存的 KV 状态，可以降低内存压力。

## 第 26–36 页：模型如何学会处理长文本

**第 26 页｜训练长上下文模型**

章节过渡页。

**第 27 页｜从短到长训练**

课件展示一种课程式训练路径：先用较短文本训练，再继续训练更长文本，最后加入长任务轨迹等材料。

图中的示例阶段为 `4K–8K → 32K–128K → 128K+`。

**意思：**先建立基础语言能力，再逐步增加长度，是一种控制训练成本、培养长距离处理能力的方法。

**第 28 页｜绝对位置编码**

模型在 token 的内容表示中加入位置向量，让它知道一个 token 出现在哪里。

**意思：**同样的词放在开头和结尾，位置不同。模型需要某种方式利用顺序信息。课件展示了可学习的位置表和用正弦、余弦计算的位置表示。

**第 29 页｜RoPE：旋转位置编码**

RoPE 对 Q、K 做与位置相关的旋转，使注意力分数能够体现位置之间的相对距离；V 不做同样的旋转。

**意思：**模型不仅能感受到“某个词在哪里”，还可以在比较时利用“两个词相隔多远”。

**第 30 页｜NoPE：不显式加入位置编码**

课件说，这类做法不加入前面展示的位置向量或 RoPE 旋转；顺序信息可以通过因果计算或循环状态等机制体现。

**意思：**即使没有显式位置编码，模型仍可能利用顺序。但这不自动保证它擅长处理超长距离依赖，仍需要相应训练和评估。

**第 31 页｜位置插值**

为了处理比训练时更长的序列，把新的长位置按比例映射到模型更熟悉的位置范围。

**意思：**像把更长的尺子压缩后放进原来的刻度范围。这样可以缓解直接遇到陌生位置的问题，但模型仍要学会使用这种映射。

**第 32 页｜YaRN**

课件介绍一种针对不同频率采用不同插值程度的方法，并调整注意力温度。

**意思：**它比“所有位置一律按同一个比例压缩”更细致：一部分维度保留局部差异，另一部分帮助扩展远距离位置。课件注明，其中温度公式是在特定模型上拟合的经验方案，不是普遍常数。

**第 33 页｜不同模型的上下文扩展路径**

表格比较各模型使用的训练长度、位置方法，以及如何达到最大上下文。

**意思：**长上下文能力可能来自渐进训练、位置缩放、不同位置表示等多种组合，不能只看宣传的最大长度。

**第 34 页｜长上下文训练数据**

课件列出四类材料：

- 长文档：书籍、代码库、多文档资料。
- 拼接样本：提高 token 利用率，但要注意样本边界。
- Agent 轨迹：包含动作与观察结果。
- 合成任务：人为安排证据、干扰项和位置。

**意思：**训练材料不仅要长，还需要让模型练习在长材料中寻找和使用信息。

**第 35 页｜训练数据如何混合**

课件比较不同模型使用自然长文本、构造监督任务和逐步增加长度的方案。

**意思：**共同思路是：有连贯的长材料，也有必须结合远处证据才能完成的任务。只把很多文字拼长，并不必然教会模型跨距离推理。

**第 36 页｜上下文并行**

把长序列分块，交给多台设备或多张卡处理；计算时设备之间交换需要的数据。

**意思：**一台设备装不下或处理太慢时，可以分工。图中讲的精确注意力仍然需要完成相应的整体计算，分工主要改变单设备内存负担和执行方式。

## 第 37–44 页：缓存——避免重复计算

**第 37 页｜提示词与 KV 缓存**

章节过渡页。

**第 38 页｜解码和多次调用中的 KV 复用**

在一次回答内部，模型生成新 token 时，会不断扩展 KV 缓存。

在 Agent 多次调用之间，如果服务支持前缀复用，之前处理过且保持一致的前缀可以被重用；新工具结果作为新输入处理后，也可能加入后续可复用的前缀。

**意思：**Agent 不必每次都从零重新计算完全相同的前文。但是否命中缓存，取决于服务实现、前缀是否匹配及缓存是否仍存在。

**第 39 页｜缓存的收益**

课件提到两项研究：复用已有注意力状态可以减少重复预填充；同一前缀被多次读取时，首次计算成本可以分摊。

**意思：**反复处理相同材料时，保存计算结果可能更划算。但**服务商收费价格与实际硬件成本是两回事**。

**第 40 页｜缓存 token 的 API 价格**

课件列举不同模型的普通输入、缓存输入和输出价格，单位是每 100 万 token 的美元价格，标注核查日期为 **2026 年 8 月 30 日**。

**意思：**缓存命中的输入往往可能比普通输入便宜，但各家的缓存创建、读取和有效期规则不同。图中价格是历史快照，不能当作现在的报价。

**第 41 页｜分页管理 KV 缓存**

图中将逻辑上连续的 KV 内容分成块，再通过“块表”映射到显存中不同的物理位置。

**意思：**像书的内容按页组织，实际存放位置由目录记录。这样更方便按需分配显存，减少因必须预留大块连续空间而产生的浪费。

**第 42 页｜RadixAttention 前缀共享**

图中展示：

1. 找到请求之间相同的前缀。
2. 后续内容不同的地方分叉。
3. 空间不足时，移除较少使用的缓存叶节点。

**意思：**多个请求如果前面有相同的系统指令或对话，可以共享相同前缀的缓存，而不是每个请求重复存一份。

**第 43 页｜根据缓存安排请求**

路由器会同时考虑哪个工作节点已有更长的可复用前缀，以及该节点当前排队有多长。

**意思：**把请求送到“缓存最多”的机器可能节省计算，但如果那台机器排队太久，也未必最快。

**第 44 页｜让提示词更容易复用缓存**

课件建议：

- 尽量保持系统指令、工具说明等前缀稳定。
- 将变化内容追加到后面。
- 避免无必要地改变时间戳、工具定义顺序等。
- 实测缓存 token、首 token 时间和缓存被清理的情况。

**意思：**缓存通常依赖可匹配的前缀；开头频繁变化，可能让后面原本相同的内容也无法直接复用。

## 第 45–51 页：压缩上下文，又不丢掉任务状态

**第 45 页｜上下文压缩**

章节过渡页。

**第 46 页｜一个压缩示例**

原始记录包括：CI 任务超时、检查日志、发现端口占用、调整 `--workers=1`、重新运行通过。

压缩后保留：

```text
目标：修复 CI 超时
原因：端口冲突
已验证：--workers=1 时测试通过
证据：/tmp/ci.log
下一步：使用已测试的配置提交 PR
```

**意思：**把长日志和过程缩短成后续工作所需的状态，同时保留证据路径。

**第 47 页｜把压缩看成“保存工作状态”**

课件用公式表达：从完整历史 `H` 生成一个受 token 预算限制的工作状态，希望 Agent 基于它继续行动时，与基于完整历史的行为尽量一致。

**意思：**一份好的压缩结果不只是“读起来像摘要”，更要让 Agent 接下来仍能做对事情。

**第 48 页｜压缩后保留什么**

课件建议区分：

- **原样保留：**目标、约束，以及最近正在进行的尝试和新结果。
- **整理成检查点：**重要决定、当前进度、ID 等。
- **移到外部并留下入口：**长日志等证据，保留关键片段和路径。
- **可以丢弃：**重复内容、已被取代的尝试。

**意思：**压缩不是把所有内容平均缩短；一些信息必须精确保留，一些信息可以随时从原始材料找回。

**第 49 页｜压缩策略要做的决定**

1. **什么时候触发：**例如接近 token 上限时，还要为下一次输出留空间。
2. **选哪部分压缩：**保护开头的重要指令、压缩较早历史、保留最近内容。
3. **用什么替换：**自然语言摘要、结构化检查点等。
4. **失败怎么办：**保留可恢复的历史，规定重试或重置方式。

**意思：**压缩既是总结问题，也是系统设计问题。尤其要在合理的对话或工具调用边界切分，避免把一次调用和它的结果拆散。

**第 50 页｜反复压缩导致信息漂移**

课件给出一个例子：

```text
原始要求：使用 CUDA 12.4
第一次摘要：使用 CUDA 12.x
第二次摘要：使用较新的 CUDA
第三次摘要：版本约束消失
```

**意思：**如果每次都只根据上一份摘要再总结，细节可能越来越模糊。版本号、路径、硬性限制等应原样保留，并在需要时回查原始证据。

**第 51 页｜怎样评估压缩是否有效**

先放入已知的约束、决定和文件信息，按实际策略压缩，再让 Agent 继续工作，检查：

- 是否记得重要约束和标识。
- 后续任务能否正确完成。
- 节省了多少 token、时间和费用。
- 多次压缩后是否仍稳定。

**意思：**最关键的检验是“压缩之后能否继续把任务做好”。
