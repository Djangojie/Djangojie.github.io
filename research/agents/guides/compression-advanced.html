Language Modeling Is Compression

为什么更会预测，就能用更少的比特保存数据？

原文位置 · 摘要、§1 Introduction

01 · 先读懂论文在问什么

题名：语言建模就是压缩。Delétang 等，2023 年预印本，ICLR 2024；本页对照 arXiv v2。题名中的“就是”指向预测概率与编码长度的联系；“压缩即智能”是更宽的解释，不能把两句话当作同一条定理。

模型给出概率
→
编码器使用概率
→
压缩后的比特
→
同一模型 + 解码器还原

阅读时带着三个问题：为什么会预测就能压缩？模型自身的体积算不算成本？压缩表现能说明哪些能力，又不能保证什么？

阅读路线：§2 建立数学关系；§3 看实验口径；§4–5 看与既有工作的关系和结论。数学细节先走完本页小例子，再回原文。

原文位置 · §2 Coding Distributions / Lossless Compression

02 · 规律为什么可以少占空间

“2 起步，每次加 2，共 12 项”可以生成整串偶数。描述不规则数据时，通常还得逐项保存偏差。这个例子展示的是算法描述长度的直觉，不是本论文的压缩实验。
无损压缩必须一字不差地恢复原数据。若编码器只说“大概是一串偶数”，任何例外都丢了。规律、例外和解码所需约定，都有信息成本。
为什么不能保证把每个文件都无损压小？
长度小于 n 比特的编码总数有限，不够为所有 n 比特文件分配不同的短编码。若不同文件得到同一码，解码时就分不清。这是计数限制，不是算法还不够聪明。
原文位置 · §2 Likelihood Maximization；式 (2)
03 · 概率如何变成信息量
如果一件事在模型看来很意外，就要用更多信息指出“这次恰好发生了它”。理想编码长度用下式衡量：
L(x) = −log₂ p(x)　比特
条长以 7 bit 为参照。小数 bit 是理想码长；实际编码会跨多个符号分摊，并有有限精度和结束信息开销。
例如 p=1/2 对应 1 bit，p=1/8 对应 3 bit。不要把它理解成“每个 token 真能单独切成 0.2 个二进制位”。
原文位置 · §2 Arithmetic Encoder / Decoder；式 (1)、图 1
04 · 动手完成一次算术编码
教学约定：符号只有 A、B，固定概率 p(A)=0.75、p(B)=0.25。编码 ABA。每一步把当前区间按概率分成两段，保留实际符号那一段。
最终区间 [0.5625, 0.703125) 内的数都能在这些约定下解出 ABA。例子选 0.625，二进制写作 0.101；解码者按相同概率逐层定位。真实实现还必须约定长度或终止符、有限精度与码流结束方式，这里不把 101 当作完整通用文件格式。
原文位置 · §2 Likelihood Maximization；式 (2)
05 · 为什么训练 loss 与码长有关
p(x₁…xₙ) = ∏ p(xᵢ | x₍＜ᵢ₎)
−log₂ p(x₁…xₙ) = Σ −log₂ p(xᵢ | x₍＜ᵢ₎)
把整句话的概率拆成每个位置的条件概率，取负对数后，乘法变成加法。这就是逐 token 预测与整段编码之间的桥。
如果一味把 A 的概率调得极高，遇到真实的 B 就会付出很大代价。训练是在所有样本上降低平均负对数概率，不是鼓励对每个答案都自信。
交叉熵是按真实数据分布计算的平均预测代价；理想算术编码的平均数据码长与之对应。常用训练 loss 若以自然对数计算，单位是 nat，除以 ln 2 才是 bit。实际文件还要计入开销。
训练集 loss 降了，是否证明模型更会处理新数据？
没有。它也可能更会记忆训练集。需要在未用于训练的数据上检查预测和压缩表现，并检查是否有数据重叠。

07 · 把模型体积加回来
教学算式：总大小 = 模型大小 + 压缩后的数据大小。假设模型 140 GB，压缩数据比例 8.3%；以 gzip 的 32.3% 作参照，暂不计它很小的程序体积。这是简化的成本演算，不是新跑的性能实验；8.3% 和 32.3% 对照的是表 1 的不同上下文条件，不能用来声称同条件性能提升。
滑块按对数变化：1–10,000 GB；GB 用十进制，模型固定按 70B × 2 byte 估算。未包含显存、时间、电力、协议或额外元数据。
若双方本来就共享同一个模型，发送方可能只需发送数据码流；若必须把模型也发过去，则要计它的大小。先讲清成本边界，才能比较。
原文位置 · §3.4 Compressors as Generative Models
08 · 从压缩器反推生成
独立教学例子：给定前缀，分别试接 A、B；如果压缩器觉得“前缀+A”更省空间，就可以偏向 A。我们用新增码长生成未归一化权重，再归一化供采样。
w(A)=2⁻ΔL(A)；p(A)=w(A)/(w(A)+w(B))
实际压缩器有头信息、块边界、字典更新等因素，码长差不一定构成理想的一致概率分布。这个演示只说明一种构造直觉，不能证明压缩器生成的文本一定正确或连贯。

09 · 上下文与分词：两个容易混淆的长度
上下文能提供眼前这段数据的统计线索；这与更新模型参数不同。分词把字节或字符组合成 token，会改变固定 token 窗口实际能容纳多少原始信息。
字节示意
t · h · e · 空格 · c · a · t
→
词块示意
the · 空格 · cat
人为分词教学示意，不是某个真实 tokenizer 的输出，也不涉及实际词表编码成本。
token 数更少不等于最终 bit 数一定更少。词表变大后，每次预测要在更多候选中分配概率，还可能需要保存词表。比较压缩时，应回到原始字节和总码长；比较上下文时，还要问固定的是 token 数还是字节数。
原文位置 · §4–5；教学延伸
10 · “压缩即智能”的边界与 Agent 应用
概念需要检查什么
无损数据压缩能否精确还原原始序列；模型与元数据是否计入
训练模型的泛化对未见数据是否预测得更好；有没有污染或记忆效应
Agent 上下文摘要通常会丢细节；后续任务是否仍能正确继续
真实任务智能还涉及行动、权限、验证、失败恢复与目标
与 lecture-03 的连接是教学延伸：把 CUDA 12.4 总结成“较新的 CUDA”会省 token，却可能毁掉任务约束。评价摘要应检查后续行为，不能仅看短了多少。
用一句话解释这篇论文，而不把“智能”说得过满。
预测概率与无损编码长度有明确联系：预测器配合编码器可做压缩，压缩视角也能帮助理解语言模型。它没有证明压缩率是人类所有智能能力的完整度量。
自测：论文中最值得质疑的实验比较条件是什么？
至少检查模型体积、分块长度、数据预处理、训练数据重叠和计算成本。raw rate 不等于包含全部成本的实用压缩收益。
